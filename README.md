## 이전 구현·준비 기록

## PC 독립 운영 준비 — 아직 호스팅 전환 전

`127.0.0.1` 주소는 로컬 실행 서버가 필요합니다. PC 종료 후에도 수집하려면 외부 호스트의 예약 작업과 공개 정적 사이트를 연결해야 합니다. 현재 GitHub 공개 저장소는 소스 보관용이며 자동 수집·Pages 운영이 활성화되었다고 주장하지 않습니다.

외부 호스트에서 `node cloud-capture.mjs`를 실행하면 이전 `records/state.json`을 전체 검증하고 메모리 DB에 복원한 뒤, 예정된 실제 원천 수집·학습을 수행합니다. 결과는 `records/state.json` 및 `cloud/site/board.json`에 저장합니다. 이 파일을 호스트의 지속 저장소에 보관해야 다음 실행에 이어집니다. `node build-static.mjs`는 외부 정적 호스팅용 `cloud/site` 화면을 준비합니다. `BOARD_STATE`와 `BOARD_OUTPUT`은 경로만 지정하며 인증값이 아닙니다.

정적 화면은 실제 저장 결과를 다시 읽습니다. 공개 방문자의 버튼은 ECB 수집 요청이 아닙니다. 새 KST 날짜에 관측이 없거나 다음 예정 점검보다 90분 이상 지연되면 마지막 정상값을 오래된 값으로 표시합니다. 실제 기록이 늘어나도 제출용 첫 두 날짜의 변화는 별도로 계산합니다. 누락 날짜를 소급 생성하지 않습니다.

보존 파일은 원자료 SHA-256·환율 계산·KST 날짜·최초/최종 조회 시각을 대조하고, 손상 시 전체 복원을 거부하여 기존 상태를 유지합니다. 클라우드 준비 관련 검사 7건 추가 후 총 46건 통과. 기존 실제 1개 날짜, 학습 64개, 예측 발행 시각의 내보내기/복원 일치도 확인했습니다. 클라우드 실제 실행·예약 활성화·PC를 끈 상태의 관측은 아직 확인 전입니다.

## GitHub 운영 연결

`.github/workflows/observe.yml`은 GitHub 호스트에서 매시 17·47분(UTC, KST의 분도 동일)에 예정 여부를 확인합니다. 실제 정상 수집 기준 간격은 4시간이며 자정과 실패 후에는 다음 호스트 예약 실행에서 처리합니다. 수동 Run workflow의 force는 캐시를 건너뛰되 최소 60초 원천 호출 간격은 지킵니다. 일정은 지연되거나 실행이 누락될 수 있습니다. GitHub의 공개 저장소 예약은 60일 동안 저장소 활동이 없으면 비활성화될 수 있으므로 마지막 점검을 확인해야 합니다. 중단된 실제 날짜를 소급 작성하지 않습니다.

수집 job은 이 저장소의 `contents: write`만, 공개 배포 job은 `pages: write`와 `id-token: write`만 요청하며 나머지는 허용하지 않습니다. GitHub가 작업 중 발급하는 인증을 사용하고 개인 API 키나 별도 배포 키를 넣지 않습니다. 공식 Actions는 확인한 commit SHA로 고정합니다. `source.zip`, `site.zip`을 `cloud-release.json`의 SHA-256과 대조하고 경로와 링크를 검사한 뒤 실행합니다. 검증된 공개 ECB 기록·학습 상태만 루트 `records-state.json`에 commit합니다. 실제 상태 변화가 없는 예약 실행은 commit/배포를 생략합니다.

호스팅 설정은 GitHub Pages Source를 GitHub Actions로 선택해야 합니다. 이 문서의 코드 준비는 실제 호스팅 성공이나 둘째 날짜의 관측 완료를 의미하지 않습니다. 전체 회귀 검사에 운영자 강제 조회와 공유 호출 간격 검사를 추가하여 현재 47건입니다.

공개 ECB 기준환율로 `round4(EUR/KRW ÷ EUR/USD)`를 계산하는 정보판. 키 없는 호출이며 거래 체결가격이나 수익 보장이 아닙니다. 기존 개인용 CRWD 프로젝트는 별도로 보존합니다.

## 저장과 호출
D1 일별 고유키는 signal_id + KST 조회 날짜. 동일 날짜의 성공은 최신 정상값으로 갱신하며 최초 조회 시각은 보존합니다. 오류는 마지막 정상값을 지우지 않습니다. 4시간 내 정상 조회는 캐시로 유지하되 새로운 KST 날짜에는 실제 호출합니다. 공유 호출 간격은 최소 60초입니다. 자동 금융거래를 실행하지 않습니다.

## 자동 관측과 학습 — 2026-10-06 추가

`start-local.ps1`을 일반 PowerShell에서 실행하고 http://127.0.0.1:8897/ 를 엽니다. 서버는 시작할 때 예정 시각을 확인하고, 이후 매분 스케줄을 점검합니다. 실제 원천 호출은 4시간 간격, 다음 KST 자정, 외부 실패 후 15분 간격입니다. 마지막 정상값은 계속 유지합니다. 브라우저를 닫아도 서버 프로세스가 살아 있으면 계속되며 PC 종료·절전·서버 종료 중에는 관측하지 않습니다. 종료 중 날짜를 실제 조회한 날짜로 소급 기록하지 않습니다.

화면의 자동 관측 일시정지/재개 설정, 다음 예정 시각, 최근 20개 관측 사건, 원천 과거 XML과 해시, 모델 상태·예측 발행·실제 검증 내역은 SQLite/D1 `automation_state`에 저장합니다. 재시작해도 유지됩니다. 수동 조회는 일시정지 중에도 가능합니다. 진행 중인 요청은 완료하되 일시정지한 뒤 추가 자동 요청을 시작하지 않습니다. 8896은 여전히 보관 결과 미리보기이며 자동 관측을 실행한다고 표시하지 않습니다.

학습은 `adaptive-drift-v1`입니다. 직전 값 유지, 최근 3회 변화 평균, 최근 10회 변화 평균의 세 후보를 순차 평가합니다. 예측에는 그 시점 이전의 값만 사용하고, 최근 최대 20회의 평균 절대 오차(MAE)로 다음 후보를 선택합니다. 동일한 평가 기간의 단순 기준 오차도 함께 표시합니다. 원천 기준일은 중복을 제거하고, 실제 조회 KST 날짜와 구분합니다. 과거 자료는 실제 ECB 역사 자료이며 과제의 서로 다른 실제 조회 날짜 두 건을 대신하지 않습니다.

새 발표 전 예측을 발행 시각과 함께 저장하고, 뒤에 처음 확인한 다음 원천 기준일의 실제 값과 한 번만 대조합니다. 과거 평가와 발행 후 평가를 분리합니다. 원천 수정은 과거 모델을 재계산하되 이미 발행한 예측·검증 오차를 덮어쓰지 않습니다. 20개 미만이면 자료 부족으로 표시합니다. 여기서 학습은 수치 모델의 갱신이며 대화형 AI 재훈련이나 실제 금융거래가 아닙니다.

초기 실제 학습 64개(2026-10-05 기준): 최근 20회 적응형 순차 예측 MAE 8.7830원, 직전 값 유지 MAE 7.8127원. 과거 평가에서 적응형이 단순 기준을 이겼다고 주장하지 않습니다. 다음 예측의 현재 선택은 직전 값 유지입니다. 발행 후 실제 새 기준일로 평가한 건수는 아직 0개입니다.

`node observe-once.mjs`는 같은 데이터 경로로 한 번 관측·학습·저장합니다. `tests/learning.test.mjs`, `tests/monitor.test.mjs`의 수치와 시계는 명시된 합성 시험 입력이며 실제 기록을 만들지 않습니다. 현재 일반 검사 39건 통과. 실제 HTTP 검사는 ECB 최신·과거 자료를 조회하는 별도 격리 DB에서 수행합니다. 공개 서버의 예약 실행은 아직 배포되지 않았습니다. Worker의 scheduled 진입점은 구현했지만 운영 예약을 활성화했다고 주장하지 않습니다.
